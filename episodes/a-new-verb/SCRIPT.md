01 open        | Watch this U R L grow. One lookup, four hundred product IDs, one sort. It has just passed eight thousand bytes.
02 shelf       | H T T P has had the same verbs for sixteen years. The last new one was PATCH, in twenty ten. Now there is another.
03 getbody     | You cannot fix this with GET. The spec is blunt. Content in a GET request has no generally defined semantics. Some servers just close the connection.
04 post        | So everyone reached for POST. Put the query in the body, and send it. It works perfectly well.
05 notapparent | Now look at what the network sees. Nothing in this request says it is a read. The spec calls that not readily apparent.
06 cost        | POST withholds two promises. Safe means nothing changed. Idempotent means sending twice is sending once. Without them, nothing caches and nothing retries.
07 query       | Change one word. QUERY takes the same body and the same content type. It declares the request safe and idempotent.
08 table       | Read the spec's own table. GET is safe but carries no body. POST carries one but promises nothing. QUERY does both.
09 cachekey    | Here is the hard part. The cache key must now include the request content. Same URL, different body, different entry.
10 name        | They nearly called it SEARCH. Three safe methods already existed, and all three came from WebDAV. The spec's reason for skipping them is one line.
11 catch       | Now the catch. Your edge has never heard this word. Allowlists written before June do not contain it, and browsers will preflight every call.
12 end         | The specification is finished. The internet is not. Start advertising Accept Query. Next episode: subagents.
